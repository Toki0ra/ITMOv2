# Design

## Context

См. `proposal.md` — Why. Модуль `practices/practice_04/app/metrics.py` содержит чистые функции без состояния и внешних зависимостей. Тесты — стандартный `unittest` в `practices/practice_04/tests/`. Команда проверки: `python -m unittest discover -s tests -v`.

## Goals / Non-Goals

**Goals:**
- Добавить одну чистую функцию с предсказуемым поведением и покрытием тестами.
- Сохранить стиль существующего модуля: простые проверки типов и явные сообщения об ошибках.

**Non-Goals:**
- Не менять существующие функции и их сигнатуры.
- Не добавлять зависимости, CLI, кэширование или потоковую обработку.

## Decisions

- **Разбиение по пробельным символам без регулярных выражений.** `text.split()` уже убирает повторные пробелы и пустые токены; регулярное выражение добавило бы зависимость и сложность без выигрыша. Альтернатива — `re.findall(r"\w+")` — отклонена, потому что она меняет семантику (удаляет пунктуацию), а это вне согласованных границ.
- **Приведение к нижнему регистру через `str.lower()`.** Это делает подсчёт нечувствительным к регистру и согласуется с ожиданиями пользователей. Альтернатива — `casefold()` — отклонена как избыточная для текущей задачи и способная неожиданно менять некоторые символы.
- **Обычный `dict` вместо `Counter`.** `dict` достаточно и не вводит новый импорт; порядок ключей соответствует первому появлению токена.
- **Проверка типа в начале функции.** Так ошибка возникает до любой обработки и совпадает с поведением `wordcount`.

## Risks / Trade-offs

- [Пунктуация остаётся частью токена: `"cat,"` и `"cat"` считаются разными] → Зафиксировано как non-goal; при необходимости будет отдельное изменение.
- [Регистр зависит от Unicode-правил `lower()`] → Приемлемо для текущего объёма; сценарии покрывают базовый ASCII-случай.
- [Большой текст целиком попадает в память] → Для библиотечной функции это ожидаемо; потоковая обработка вне границ.
