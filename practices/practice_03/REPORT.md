# REPORT: Локальная модель и конфигурация

## Что сделано
- Настроен локальный инференс через Ollama с OpenAI-совместимым API на http://localhost:11434
- Подготовлены две конфигурации модели через Modelfile: рабочая (агент) и тестируемая
- Реализованы скрипты экспериментов и проверок: сравнение ответов модели с эталонами на вопросах по демо‑сервису
- Настроен read-only агент OpenCode для опроса модели по файлам демо‑проекта
- В репозитории фиксируются результаты запросов и сравнения (lab/records/*)

## Теория (коротко)
- Ollama — локальный менеджер моделей, который поднимает HTTP‑сервер с OpenAI‑совместимым API. Можно пулить готовые сборки моделей и/или собирать собственные через Modelfile.
- Modelfile описывает основу (FROM <model>), параметры инференса (PARAMETER num_ctx, temperature и др.) и системное сообщение (SYSTEM). Командой `ollama create <name> -f Modelfile` создаётся локальный тэг модели.
- Квантизация влияет на память и скорость. Чем сильнее квантизация, тем меньше потребление RAM/VRAM, но возможна деградация качества.
- Контекст (num_ctx) — максимальная длина входа/выхода в токенах. Больший контекст = больше память/время. Предел в OpenCode — инструментальный лимит; реальный предел задаётся моделью/сборкой.
- Детерминизм: temperature и seed делают ответы более повторяемыми для проверки.

## Пошаговый запуск (Windows/WSL)
1. Установить Ollama.
   - Windows: установить приложение Ollama с официального сайта и запустить. Сервер поднимется на http://localhost:11434.
   - WSL/Linux: `curl -fsSL https://ollama.com/install.sh | sh` и затем `ollama serve`.
2. Загрузить базовую модель для тестов:
   - `ollama pull qwen3.5:4b`
3. Собрать локальные теги моделей из Modelfile (из директории practices/practice_03/lab):
   - `ollama create itmo-local -f Modelfile` — тестируемая конфигурация (с SYSTEM‑промптом)
   - `ollama create itmo-agent -f Modelfile.agent` — конфигурация для агента OpenCode
   - Проверка: `curl http://localhost:11434/api/tags` и убедиться, что itmo-agent присутствует
4. Прогнать демо‑сервис и тесты (из practices/practice_03/lab):
   - `make test` — выполнит `python3 -m unittest -v` в lab/demo
5. Мини‑эксперименты с локальной моделью:
   - `make experiment-baseline` — вопрос без системного промпта
   - `make experiment-system` — тот же вопрос с системным промптом из lab/system.txt
   - Артефакты: lab/records/baseline.json, lab/records/system.json
6. Пять вопросов к модели и сравнение с эталонами:
   - `make questions` — задаёт 5 вопросов из lab/QUESTIONS.md, контекст только файлы lab/demo/*; сохранит lab/records/questions_answers.json
   - `make compare` — сформирует lab/records/comparison.md с PASS/FAIL по критериям
7. OpenCode read‑only агент:
   - Конфиг уже в lab/demo/opencode.json. Модель: ollama/itmo-agent, провайдер baseURL http://localhost:11434/v1, разрешены только read/glob/grep.
   - Запускайте сессии в OpenCode, выбирая агента local-guide. Эталоны из lab/ANSWERS.md в тестовые сессии не передаются.

Альтернатива: LM Studio
- Можно использовать LM Studio как локальный сервер (OpenAI‑совместимый порт, по умолчанию 1234). Для этого замените baseURL в lab/demo/opencode.json на http://localhost:1234/v1 и выберите соответствующую модель в LM Studio.

## Выбор модели и параметры
- Провайдер: Ollama (локальный сервер)
- Базовая модель (для тестируемых сессий): `qwen3.5:4b`
  - Причины выбора: небольшой размер (быстрее на CPU, укладывается в 16 ГБ RAM), приемлемое качество для учебных задач, стабильность на CPU без дискретной GPU
  - Квантизация: дефолтная Ollama для данной сборки (CPU‑friendly; зависит от установленного бандла модели)
  - Длина контекста (`num_ctx`): 4096
  - Температура: 0.2 (более детерминированные ответы при проверках)

- Агентная модель (для рабочего агента OpenCode): `ollama/itmo-agent`
  - Конфиг задаётся в `lab/demo/opencode.json` (limit.context 65536 — верхняя граница в OpenCode, фактическая длина определяется моделью)
  - Modelfile агента: `lab/Modelfile.agent`

## Что устроено как есть
- Стандартная библиотека Python, без внешних зависимостей; HTTP‑вызовы к Ollama выполняются через urllib.request.
- Все результаты экспериментов и QA сохраняются в lab/records, что упрощает проверку и воспроизводимость.

## Обоснование выбора
- CPU‑инференс: на интегрированной графике без гарантированной VRAM упор делается на CPU; 4B‑модель позволяет держать задержки и потребление памяти на приемлемом уровне
- Контекст 4096 для тестируемых сессий — достаточен для чтения небольших файлов демо‑сервиса и вопросов из `QUESTIONS.md`
- Агенту задана высокая граница контекста в OpenCode (до 64k), чтобы не ограничивать его на уровне инструмента; фактическая доступная длина определяется моделью и окружением

## Что настроено в репозитории
- Modelfile: `lab/Modelfile` — системный промпт требует отвечать только по предоставленным фактам, при отсутствии ответа — явно говорить об этом
- Modelfile.agent: `lab/Modelfile.agent` — параметры для агентной модели
- opencode.json: `lab/demo/opencode.json` — провайдер Ollama (`http://localhost:11434/v1`), агент `local-guide` с правами только на чтение (`read/glob/grep`), модель‑алиас `ollama/itmo-agent`
- make test: корневой `Makefile` вызывает `lab/demo` юнит‑тесты (стандартная библиотека Python 3.10+)

## Риски и ограничения
- Возможны более высокие задержки на CPU по сравнению с дискретной GPU; при необходимости снизить `num_ctx` до 2048
- При нехватке памяти стоит перейти на ещё меньшую модель (например, 2B) или более сильную квантизацию
- Предел 64k в OpenCode — это ограничение со стороны инструмента; реальный предел зависит от сборки модели в Ollama
