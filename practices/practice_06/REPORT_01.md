# Отчёт 1. Атаки на исходный сервис

## Методика

Атаки выполнялись только против локального процесса Mini Shop с синтетическими данными. Скрипт: `lab/attack_demo.py`. Сырые результаты: `evidence/before/attacks.json`. Модель угроз: `THREAT_MODEL.md`.

Команда:

```bash
cd practices/practice_06/lab
python attack_demo.py --output ../evidence/before/attacks.json
```

Исходный сервис был уязвим: **16 из 16** атак достигли эффекта.

## Найденные проблемы

| ID | Проблема | Вектор | Факт до фикса |
|---|---|---|---|
| T1 | IDOR профиля и отсутствие аутентификации | `GET /profile?id=2` | `200`, отдан `TEST_BOB` |
| T2 | SQL-инъекция в профиле | `GET /profile?id=0 OR 1=1` | `200`, отданы оба профиля |
| T3 | SQL-инъекция и перечисление в поиске | `GET /search?q=' OR '1'='1` | `200`, отданы оба профиля |
| T4 | Подмена роли клиентским заголовком | `GET /admin/export` + `X-Role: staff` | `200`, экспорт без сессии |
| T5 | Чтение чужого чека | `GET /files?user=bob&path=receipt.txt` | `200`, `TEST_BOB receipt` |
| T6 | Выход из каталога пользователя | `path=../../private/operator-note.txt` | `200`, `TEST_ONLY_OPERATOR_SECRET` |
| T7 | Подмена цены заказа | `POST /orders {product: chair, price: 1}` | `201`, `price: 1` |

| T12 | Утечка паролей и токенов | `GET /debug/logs` | `200`, в журнале `learn-alice` и токены |
| T13 | Злоупотребление инструментами | `POST /assistant/execute` `export_profiles` от клиента | `200`, экспорт всех профилей |
| T14 | Чтение служебной заметки через инструмент | `read_file` `private/operator-note.txt` | `200`, секрет отдан без сессии |

| T16 | Разрушительный инструмент | `delete_tree` `.` | `200`, каталог стенда удалён |

## Корневые причины

1. Многие маршруты не требовали валидной сессии: `/profile`, `/search`, `/orders`, `/files`, `/debug/logs`, `/assistant/*`.
2. Роль и владелец не выводились из серверной сессии: `/admin/export` доверял `X-Role`.
3. SQL-запросы собирались f-строками: `/profile`, `/search`, `/assistant/context`.
4. Не проверялся владелец ресурса: профиль, заказ, чек, контекст.
5. Исполнитель инструментов принимал любое решение LLM без проверки роли и белого списка.
6. Цена заказа бралась из тела запроса.
7. Вывод отзывов не экранировался.
8. Журнал писал пароли и заголовки с токенами.
9. Ошибки 500 возвращали `str(exc)` и тип исключения.

## Вывод

Исходный сервис соответствует учебной задумке: критические данные доступны без авторизации, а AI-помощник может быть использован как усилитель атаки. Все найденные проблемы воспроизводимы и зафиксированы в `evidence/before/attacks.json`.
