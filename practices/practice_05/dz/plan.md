# Plan (Spec Kit)

## Второй фреймворк

Выбран **GitHub Spec Kit**. Артефакты повторяют его форму: `constitution.md`, отдельные `spec.md` для каждой команды, общий `plan.md`, `tasks.md`. Как и требует Spec Kit, код появляется только после согласования спецификаций и контракта.

## Согласование двух команд

| Вопрос | Команда UI | Команда логики | Итог |
|---|---|---|---|
| Кто считает частоты | не считает, только показывает | считает | логика |
| Формат результата | таблица `word/count` | `items[]` | контракт `items[]` |
| Пустой текст | состояние `empty` | `items: []`, счётчики 0 | оба поведения |
| Ошибки | показывает `error.message` | отдаёт `error.code` + `error.message` | единый формат ошибки |
| Валидация `limit` | не отправляет вне 1..100 | дублирует проверку, 400 | защита на двух уровнях |
| Сортировка | не меняет порядок | сортирует и ограничивает | логика |

Изменения контракта после согласования не потребовались.

## Архитектура

```
Browser (static/index.html)
        |
        | POST /api/analyze  (JSON по contracts/api.md)
        v
app/server.py  --->  app/wordstats.py
  HTTP, валидация       чистый алгоритм
  и сериализация        (без HTTP)
```

- `app/wordstats.py` — чистая функция `analyze(text, limit)`, не знает про HTTP.
- `app/server.py` — `ThreadingHTTPServer`, разбор JSON, коды ошибок, раздача `index.html`.
- `app/static/index.html` — экран, состояния и вызов API.
- `tests/test_logic.py` — юнит-тесты логики.
- `tests/test_http.py` — HTTP и сквозной контракт.

## Технологии

Python 3.10+, только стандартная библиотека. Тесты — `unittest`. Запуск — `make test`.

## Риски

- [Расхождение UI и API по формату ошибки] → контракт фиксирует `error.code/message`; тест проверяет оба поля.
- [Разные правила токенизации у команд] → токенизация описана только в спецификации логики, UI её не дублирует.
- [Кириллица в JSON] → `ensure_ascii=False`, `Content-Type: application/json; charset=utf-8`.
