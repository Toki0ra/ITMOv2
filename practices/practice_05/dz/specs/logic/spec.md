# Спецификация логики — Word Frequency Explorer

Команда 2. Экран и состояния описаны в `../ui/spec.md`; формат обмена — в `../../contracts/api.md`.

## Данные

Вход:

```json
{"text": "string", "limit": 3}
```

Выход при успехе (200):

```json
{
  "items": [{"word": "string", "count": 1}],
  "total_words": 1,
  "unique_words": 1
}
```

## Алгоритм

1. Проверить, что `text` — строка, а `limit` — целое число.
2. Если `text` пуст или состоит только из пробельных символов — вернуть `items: []`, `total_words: 0`, `unique_words: 0`.
3. Разбить текст по пробельным символам (`str.split()` без аргументов).
4. Привести каждый токен к нижнему регистру через `str.lower()`.
5. Посчитать частоты.
6. Отсортировать пары по убыванию `count`, при равенстве — по возрастанию `word`.
7. Взять первые `limit` пар.
8. `total_words` — число всех токенов, `unique_words` — число уникальных ключей.

## Правила валидации

- `text` отсутствует или не строка → `400`, код `invalid_text`.
- `limit` отсутствует → по умолчанию `3`.
- `limit` не целое число или вне диапазона `1..100` → `400`, код `invalid_limit`.
- Длина `text` больше `10000` символов → `413`, код `text_too_long`.
- Тело запроса не является JSON-объектом → `400`, код `invalid_body`.
- Неизвестный путь → `404`, код `not_found`.
- Неизвестный HTTP-метод для `/api/analyze` → `405`, код `method_not_allowed`.

## Условия приёмки

1. `analyze("b a b c a b", 3)` возвращает `b:3, a:2, c:1`.
2. При равных частотах порядок алфавитный.
3. `limit` ограничивает выдачу, но не влияет на `total_words` и `unique_words`.
4. Пустой текст даёт пустой `items` и нулевые счётчики.
5. Все коды ошибок и HTTP-статусы соответствуют контракту.

## Вне границ

- Стемминг, удаление пунктуации, языковые стоп-слова, кэш, база данных, аутентификация.
